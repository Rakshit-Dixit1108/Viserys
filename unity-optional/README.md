# Dracarys — Optional Unity Upgrade Path

The Dracarys cinematic **works today** without any of this — it's built
directly into the Electron app (`frontend/src/components/DracarysOverlay.tsx`)
using SVG, Framer Motion, and Web Audio, with no external asset dependency.
Type "Dracarys" into the chat to see it.

This folder is an **optional** upgrade if you later get a 3D dragon asset
(from the Unity Asset Store or a modeler) and want a higher-fidelity
standalone cinematic instead. It is scripts only, not a full Unity project
export, because:

- A 3D dragon model, rig, and animations are art assets that have to come
  from an artist or an asset pack — no code-generation tool, including this
  one, can produce game-ready 3D art.
- A Unity project also needs `.meta` files, `ProjectSettings/`, and package
  manifests generated by the Unity Editor itself; those aren't meaningfully
  hand-writable outside the Editor.

## What's here and what it does

- `Scripts/DracarysController.cs` — sequences fly-in → roar → fire breath →
  fly-away by triggering Animator parameters and a fire ParticleSystem.
  Fully functional logic; it just needs those GameObjects to exist.
- `Scripts/CameraShake.cs` — a working, dependency-free camera shake.

## Setting it up (once you have a dragon asset)

1. Create a new 3D Unity project (2022 LTS+).
2. Import your dragon asset; add an Animator Controller with **trigger**
   parameters named `FlyIn`, `Roar`, `BreatheFire`, `FlyAway`, wired to the
   asset's corresponding animation clips.
3. Add a fire `ParticleSystem` as a child of the dragon's head/mouth bone.
4. Drop `Scripts/*.cs` into `Assets/Scripts/`.
5. Add an empty GameObject, attach `DracarysController`, and drag in the
   Animator, ParticleSystem, an AudioSource + roar clip, a Light for the eye
   glow, and your Main Camera.
6. Build a Windows standalone executable (File → Build Settings → Windows).
7. In the Electron app, set `DRACARYS_EXE_PATH` to the built `.exe` in
   `frontend/.env` (see `frontend/electron/main.js` — `launchUnityExecutable`
   is already wired to spawn it if the path is configured, falling back to
   the built-in overlay otherwise).
